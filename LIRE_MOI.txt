LOKA V24 — BLOC 12.15
=======================

OBJET
-----
Fenêtre de certification / gel temporaire des générations.

Le problème opérationnel traité est réel :
les preuves 12.8, 12.9, 12.10, FINAL_RC et REHEARSAL sont attachées à une
génération précise. Une nouvelle génération entre deux étapes les rend
immédiatement périmées.

Le 12.15 protège la génération choisie pendant la recertification finale.

OUVERTURE
---------
La fenêtre ne peut être ouverte que si :

- readiness = READY_CANDIDATE
- production publique = LEGACY
- requested_mode = LEGACY
- V24 approuvé = NON
- identité/fingerprint publics disponibles

Phrase exacte :

GELER CERTIFICATION TARNOS

DURÉE
-----
45 minutes maximum.

La fenêtre mémorise :
- generatedAt
- moteur public
- scène
- fingerprint
- readiness
- fingerprint readiness

PENDANT LA FENÊTRE
------------------
Bloqué :
- bouton « Générer la météo »
- génération cron

Autorisé :
- tous les audits 12.8 -> 12.12
- Preview V24 nécessaire au 12.12
- rollback drills
- UNE génération spéciale de cutover source=go_live_12_13

Le forecast officiel courant reste inchangé pendant la recertification.

RÉPONSE DU BOUTON GÉNÉRER
-------------------------
Si l'utilisateur tente une génération manuelle pendant la fenêtre :

HTTP 423

certification_window_generation_blocked:<window_id>

Cela est volontaire.

CRON
----
Si le cron de 05:00 tombe pendant la fenêtre :
la génération de cette ville est simplement ignorée.

Un événement append-only :
GENERATION_BLOCKED
est enregistré.

Aucune erreur météo globale n'est déclenchée.

SÉCURITÉ ASYMÉTRIQUE
--------------------
Si D1 12.15 lui-même est indisponible :

- génération météo normale :
  FAIL-OPEN
  La météo Legacy continue. Le verrou opérationnel ne doit jamais casser la
  production météo.

- activation V24 :
  FAIL-CLOSED
  Le 12.13 exige une fenêtre ACTIVE et courante. Aucun GO LIVE sans preuve
  12.15.

NOUVEAU PROCESS FINAL
---------------------
Quand le 12.14 passe :

RECERTIFICATION_REQUIRED

Faire :

1. Ouvrir « Fenêtre certification 12.15 »
2. Taper :
   GELER CERTIFICATION TARNOS

3. Vérifier :
   ACTIVE
   même generatedAt
   même fingerprint
   expiration < 45 min

4. Sans générer de nouvelle météo :
   12.8  PASS 16/16
   12.9  PASS 24/24
   12.10 PASS
   12.11 FINAL_RC_PASS
   12.12 REHEARSAL_PASS

5. Revenir immédiatement à 12.13.

6. Le GO LIVE 12.13 doit afficher :
   Fenêtre certification 12.15 = ACTIVE

7. Préparer puis confirmer le GO LIVE.

8. La génération de cutover 12.13 est la seule génération autorisée pendant
   le gel.

FIN DE FENÊTRE
--------------
Après un vrai essai GO LIVE :

- succès GO_LIVE_ACTIVE :
  fenêtre = CONSUMED

- GO_LIVE_ABORTED :
  fenêtre = CONSUMED

Si l'opérateur annule :
fenêtre = CANCELLED

Si 45 minutes passent :
fenêtre = EXPIRED

Une fenêtre expirée ne peut jamais être réutilisée.

ROLLBACK MANUEL
---------------
Le bouton Admin global « Revenir à Legacy » annule aussi toute fenêtre
certification ACTIVE.

Les rollback drills internes 12.10 et 12.12 ne l'annulent PAS.

12.13 RENFORCÉ
--------------
Après installation du 12.15, le 12.13 ajoute un contrôle bloquant :

certification_window_current

Il exige :
- fenêtre ACTIVE
- même generatedAt
- même fingerprint
- readiness READY_CANDIDATE

Donc une course entre recertification et nouvelle génération n'est plus
possible par le workflow normal.
