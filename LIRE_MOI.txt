LOKA V24 — BLOC 12.14
=======================

OBJET
-----
Supervision production et stabilisation post-GO-LIVE.

Le Bloc 12.13 reste le SEUL mécanisme d'activation officielle.
Le Bloc 12.14 n'active jamais V24 et ne déclenche jamais de rollback global
automatique.

POURQUOI 12.14
--------------
Le 12.13 est volontairement strict : une nouvelle génération rend les preuves
FINAL_RC / REHEARSAL précédentes périmées.

Le 12.14 rend le process opérationnel et lisible sur la durée :

AVANT GO LIVE
- WAITING_READINESS
- RECERTIFICATION_REQUIRED
- GO_LIVE_ELIGIBLE
- PRE_GO_LIVE_BLOCKED

APRÈS GO LIVE
- V24_LIVE_HEALTHY
- V24_LIVE_STABLE
- V24_LIVE_WATCH
- ROLLBACK_RECOMMENDED

COMPORTEMENT AVANT GO LIVE
--------------------------
Avec l'état actuel :
readiness = NOT_READY
production = LEGACY

le statut attendu est :

WAITING_READINESS

La recommandation est volontairement :
continuer Shadow et NE PAS refaire 12.8→12.12 après chaque génération.

Lorsque READY_CANDIDATE sera atteint :

- si FINAL_RC / REHEARSAL sont périmés :
  RECERTIFICATION_REQUIRED

  Le panneau dira de refaire, sur UNE seule génération courante :
  12.8 -> 12.9 -> 12.10 -> 12.11 -> 12.12

- si toutes les preuves 12.13 sont alignées :
  GO_LIVE_ELIGIBLE

Le GO LIVE reste alors une action humaine dans 12.13.

COMPORTEMENT APRÈS GO LIVE
--------------------------
Chaque génération météo enregistre automatiquement un snapshot de supervision.

V24_LIVE_HEALTHY
La génération courante est V24, le garde-fou est PASS, le manifest est valide
et le backup Legacy est disponible.

V24_LIVE_STABLE
6 générations V24 consécutives saines sont observées.

V24_LIVE_WATCH
Une génération est tombée en fallback Legacy.
Cela NE déclenche PAS un rollback global : la séparation historique entre
fallback local et rollback global est conservée.

ROLLBACK_RECOMMENDED
Exemples :
- deux fallbacks V24 consécutifs ;
- surface publique indisponible ;
- manifest invalide ;
- backup Legacy indisponible ;
- garde-fou incohérent alors que V24 est armé.

Même dans ce statut, 12.14 ne rollback pas automatiquement.
L'opérateur utilise le bouton global « Revenir à Legacy » après analyse.

POURQUOI PAS DE ROLLBACK AUTOMATIQUE
------------------------------------
Le design LOKA distingue volontairement :

1. fallback d'une génération
2. rollback global d'administration

Une météo ponctuellement ambiguë ne doit pas désarmer toute la V24.
Le 12.14 recommande un rollback si l'incident persiste ou devient structurel,
mais laisse l'action globale explicite et auditée.

ROUTES ADMIN
------------
GET  /api/admin/production-supervisor?city=tarnos
POST /api/admin/production-supervisor/snapshot?city=tarnos

Le pipeline crée aussi automatiquement un snapshot après chaque génération
commise. Une panne du superviseur ne peut jamais faire échouer une génération
météo.

Supervision production 12.14

- phase PRE_GO_LIVE / V24_LIVE

- REHEARSAL courant

- stabilité V24 / 6
- recommandation
- 12 derniers snapshots

SUITE
-----
Il n'est pas nécessaire d'ajouter un autre mécanisme d'activation.
12.13 = activation.
12.14 = exploitation / stabilisation.

Quand READY_CANDIDATE arrivera, le 12.14 indiquera précisément quand refaire
la chaîne finale et quand le 12.13 devient réellement ELIGIBLE.
