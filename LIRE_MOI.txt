LOKA V24 — BLOC 12.4
======================

OBJECTIF
--------
Premier CUTOVER PUBLIC RÉEL mais strictement conditionnel.

Une génération devient officiellement V24 uniquement si :

1. requested_mode = V24
2. v24_approved = true
3. readiness = READY_CANDIDATE
4. décision V24 valide
5. preuve APPROVED dans l'audit
6. TOUS les garde-fous du Bloc 12.3 = PASS

Sinon :
MOTEUR PUBLIC = LEGACY

AUCUNE NOUVELLE MIGRATION D1.
Les migrations 0003 et 0004 doivent déjà être présentes.

COMMENT LE CUTOVER FONCTIONNE
-----------------------------
engineMode 12.4 vérifie d'abord les conditions globales :

LEGACY demandé
→ resolver = LEGACY

V24_PREVIEW
→ resolver = LEGACY

V24 mais readiness insuffisant
→ resolver = LEGACY

V24 sans approbation
→ resolver = LEGACY

V24 + approbation + READY_CANDIDATE + scène valide
→ resolver = V24 ARMÉ
→ le garde-fou génération 12.3 reste obligatoire

Ensuite engineRuntime applique la décision finale :

resolver V24 + guard PASS
→ génération publique V24

resolver V24 + guard BLOCKED
→ génération publique LEGACY
→ generationFallbackRequired = true

AUCUN "DEMI V24"
----------------
Quand une génération passe en V24, le runtime remplace ENSEMBLE :

- forecast.scene
- subtitle
- summaryLines
- mainVerdict
- rainVerdict
- notableEvent
- decisionLog public
- diagnostics.scene
- diagnostics.subtitle
- diagnostics.summaryLines
- diagnostics.decisionLog
- sceneClassifierProduction

Cela est important car storage/db.ts reconstruit scene/subtitle/summaryLines
depuis diagnostics_json lors de la lecture D1.

Le produit V24 complet est sauvegardé dans :
diagnostics.v24OfficialProduct

Le produit Legacy complet est conservé dans :
diagnostics.legacyPublicFallback

FAIL-SAFE À LA LECTURE
----------------------
Même après sauvegarde, chaque surface publique revérifie :

sceneEngine.effectiveProduction = V24
+
v24ActivationGuard.status = PASS
+
v24OfficialProduct valide

Si une incohérence est détectée :
la requête publique reconstruit immédiatement le fallback Legacy.

Cela protège :
- /api/latest
- /api/decision
- /
- /instagram

SURFACES PUBLIQUES
------------------
Quand la génération effective est LEGACY :

/api/latest  -> Legacy
/api/decision -> Legacy
/             -> dashboard Legacy
/instagram    -> Studio Legacy

Quand la génération effective est V24 PASS :

/api/latest  -> forecast public V24
/api/decision -> forecast public V24
/             -> nouveau dashboard officiel V24
/instagram    -> nouveau Studio officiel V24

Les routes QA restent séparées :

/instagram24
= Shadow / QA

/preview24
= prépublication V24

/instagram24-preview
= Studio prépublication V24

ROLLBACK
--------
Le bouton "Revenir à Legacy" garde priorité absolue.

Après rollback :
requested_mode = LEGACY
v24_approved = 0

La prochaine génération est Legacy.

Les requêtes publiques disposent également d'un fallback de lecture si un
produit V24 stocké est incomplet ou invalide.

ÉTAT ACTUEL
-----------
Avec ton readiness actuel NOT_READY :

Bloc 12.4 NE CHANGERA RIEN au produit public.

Même si le code de cutover existe :
resolver = LEGACY
dashboard = Legacy
Instagram = Legacy

Donc le déploiement du Bloc 12.4 n'est PAS une activation anticipée.

----------------------
1. Déployer Bloc 12.4.

   Production = LEGACY

TEST FUTUR READY_CANDIDATE
--------------------------
Après double confirmation :

Nouvelle génération
→ si guard PASS :
   Production = V24

→ si guard BLOCKED :
   Production = LEGACY
