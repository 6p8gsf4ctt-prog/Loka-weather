LOKA V24 — BLOC 12.3
======================

OBJECTIF
--------
Installer le garde-fou EXACT de chaque génération avant le futur cutover V24.

Ce bloc utilise l'autorisation du Bloc 12.2, mais NE BASCULE TOUJOURS PAS
les surfaces publiques.

AUCUNE MIGRATION D1.
La migration 0004 du Bloc 12.2 doit déjà être appliquée.

--------

GARDE-FOUS PAR GÉNÉRATION
-------------------------
V24 ne peut être déclaré "prêt pour cutover" que si TOUS ces contrôles passent :

1. requested_mode = V24
2. v24_approved = true
3. événement APPROVED présent dans l'audit append-only
4. readiness courant = READY_CANDIDATE
5. décision scene24 présente
6. scene24Error absent
7. dayProfile24 présent
8. au moins 4 modèles météo disponibles
9. futur payload V24 construit sans erreur
10. score gagnant >= 55
11. confiance = MEDIUM ou HIGH
12. gap gagnant / runner-up >= 7 points
    - si aucun runner-up : score >= 70 ET confiance HIGH
13. scènes 08/17 brouillard :
    visibilityMinKm physique obligatoire
14. scène 22 orage :
    au moins 1 h d'orage ET support >= 60 %

STATUTS
-------
NOT_ARMED
- LEGACY ou V24_PREVIEW demandé
- aucune tentative de production

BLOCKED
- V24 est demandé mais un garde-fou échoue
- fallbackRequired = true
- fallback = LEGACY

PASS
- tous les garde-fous de cette génération passent
- activationReadyForCutover = true
- MAIS cutover public encore verrouillé au Bloc 12.3

IMPORTANT
---------
Même avec :
requested_mode = V24
v24_approved = true
readiness = READY_CANDIDATE
guard = PASS

le Bloc 12.3 conserve :
effectiveProduction = LEGACY
publicCutoverLockedUntilBloc12_4 = true

Le Bloc 12.4 sera donc le premier bloc autorisé à brancher les surfaces
publiques sur le produit V24 d'une génération PASS.

FALLBACK DE GÉNÉRATION
----------------------
Si un garde-fou échoue :
- forecast Legacy reste intact
- sceneEngine.generationFallbackRequired = true
- v24ActivationGuard.status = BLOCKED
- la raison exacte est sauvegardée
- aucune exception V24 ne bloque la météo officielle

Le rollback administratif global du Bloc 11/12 reste disponible à tout moment.

NOUVELLE ROUTE ADMIN
--------------------
GET /api/admin/engine/activation-check?city=tarnos
Authorization: Bearer ADMIN_TOKEN

Elle recalcule les garde-fous sur le forecast courant et renvoie :
- résolution moteur
- statut PASS / BLOCKED / NOT_ARMED
- chaque check OK / NON
- fallback LEGACY
- cutover public verrouillé

ADMIN MOBILE
------------
Nouveau bouton :
"Tester les garde-fous V24"

Il affiche chaque critère individuellement.

TEST AUJOURD'HUI
----------------
Avec l'état actuel :
requested_mode = LEGACY
readiness = NOT_READY

Résultat attendu :
status = NOT_ARMED
activationReadyForCutover = NON
production = LEGACY

Si tu actives V24_PREVIEW :
status reste NOT_ARMED
car Preview n'est jamais un mode de production.

Quand un jour READY_CANDIDATE + double confirmation seront acquis :
requested_mode = V24
v24_approved = OUI

Le garde-fou pourra alors retourner :
PASS
ou
BLOCKED avec la raison précise de la génération.

PROCHAINE ÉTAPE
---------------
Bloc 12.4 :
brancher enfin les surfaces publiques sur V24 UNIQUEMENT pour une génération
dont le garde-fou 12.3 est PASS, avec fallback immédiat vers Legacy sinon.
