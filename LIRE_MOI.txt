LOKA V24 — BLOC 12.10
=======================

OBJECTIF
--------
Tester le VRAI rollback administratif, de façon contrôlée, avant le GO LIVE.

Ce bloc est volontairement différent des tests 12.8 :

12.8
= simulations/injections sur clones et politique de récupération.

12.10
= vraie écriture temporaire dans engine_control
  + vrai rollback global utilisé par l'Admin.

AUCUN forecast n'est généré pendant le drill.
Aucune approbation V24 n'est accordée.
Aucune publication Instagram n'est déclenchée.

REFACTOR IMPORTANT
------------------
Le rollback manuel /api/admin/engine/rollback utilisait auparavant :

rollbackToLegacy()
puis
auditRollback()

Le Bloc 12.10 centralise désormais cette séquence dans :

src/storage/globalRollback.ts
executeGlobalRollback()

Cette fonction applique une règle fondamentale :

1. rollbackToLegacy() d'abord
2. vérification requested_mode = LEGACY
3. vérification v24_approved = 0
4. audit/cancel des challenges ensuite
5. une panne d'audit ne peut JAMAIS annuler le rollback

Le bouton Admin normal ET le drill 12.10 utilisent exactement cette même
fonction.

PRÉCONDITIONS DU DRILL
----------------------
Le serveur REFUSE le test si l'état de départ n'est pas sûr.

Il exige :

- requested_mode = LEGACY
- v24_approved = NON
- surface publique effective = LEGACY
- forecast manifesté / fingerprint disponible
- aucun challenge V24 en attente
- dernier Bloc 12.8 = PASS
- dernier Bloc 12.9 = PASS

Ainsi le test ne démarre jamais depuis un V24 réellement approuvé.

PHRASE DE CONFIRMATION
----------------------
Le bouton demande de taper exactement :

TESTER ROLLBACK TARNOS

Sans cette phrase :
REFUSED
aucune mutation.

SÉQUENCE RÉELLE
---------------
ÉTAPE A
engine_control est réellement écrit en :

requested_mode = V24_PREVIEW
v24_approved = 0

Vérification :
la surface publique reste exactement la même génération Legacy.

ÉTAPE B
executeGlobalRollback()

Attendu :
requested_mode = LEGACY
v24_approved = 0

ÉTAPE C
engine_control est réellement écrit avec un intent V24 NON APPROUVÉ :

requested_mode = V24
v24_approved = 0

Ce n'est pas une activation :
sans approval, V24 ne peut pas devenir officiel.

La surface publique doit rester strictement inchangée.

ÉTAPE D
executeGlobalRollback() à nouveau.

Attendu final obligatoire :

requested_mode = LEGACY
v24_approved = 0

CONTRÔLES FINAUX
----------------
Le drill vérifie ensuite :

- forecast.generatedAt identique avant/après
- moteur public identique
- scène identique
- fingerprint identique
- aucune approbation V24 observée
- état final LEGACY
- rollback global vérifié

EMERGENCY CLEANUP
-----------------
Si une étape intermédiaire lance une exception après modification de
engine_control, rollbackDrill.ts déclenche immédiatement :

executeGlobalRollback(..., "bloc12_10_emergency_cleanup")

Le rapport devient FAIL, même si le cleanup réussit.

Donc :
- cleanup utilisé = sécurité fonctionnelle
- mais le Bloc 12.10 n'est PAS validé

Si le cleanup échoue lui-même :
ne pas poursuivre.
Vérifier immédiatement l'Admin et utiliser le bouton manuel "Revenir à Legacy".

AUDIT
-----
Chaque drill est enregistré dans :

rollback_drill_audit

L'audit enregistre notamment :
- avant/après
- fingerprint avant/après
- Preview vérifié
- intent V24 verrouillé vérifié
- rollback vérifié
- identité publique inchangée
- cleanup éventuel

La table impose :
production_forecast_mutated = 0
v24_approval_granted = 0

IMPORTANT
---------
Contrairement aux Blocs 12.8 et 12.9, ce test MODIFIE volontairement
engine_control pendant quelques instants.

C'est précisément le but du Bloc 12.10.

Mais il ne touche jamais au forecast officiel et ne peut démarrer que lorsque
V24 n'est pas approuvé.
