LOKA V3 — ETAPE 7L.5 — AUDIT CAUSE RACINE BROWSER RUN

PREREQUIS
- 7L.4 deja installe.
- Workers KV INSTAGRAM_MEDIA deja configure.
- Browser Run binding BROWSER deja configure.
- Aucune migration D1 supplementaire.

CAUSE RACINE CORRIGEE
1. Le renderer recevait un payload en argument mais demandait ensuite a Browser Run de recharger /instagram-v3-preview.
2. Cette route relisait le payload officiel dans D1, qui peut encore etre un ancien payload V2 sans analysis V3 apres un deploiement en cours de journee.
3. Dans ce cas aucun canvas #page1/#page2 n'etait cree ; waitForSelector attendait jusqu'au timeout 6002.
4. networkidle0 ajoutait une attente inutile et fragile.

NOUVELLE ARCHITECTURE
- Browser Run recoit directement le HTML construit a partir du payload V3 exact a capturer.
- Il ne recharge plus /instagram-v3-preview.
- waitForSelector seul est utilise pour le canvas rendu ; networkidle0 est supprime.
- Le master et le logo sont verifies avant Browser Run pour echouer immediatement s'ils manquent.
- Si l'officiel du jour est encore V2 :
  a) utilise une generation V3 archivee du meme jour si disponible ;
  b) sinon genere une V3 fraiche sans remplacer l'officiel V2.
- Un payload sans analysis V3 n'est jamais envoye a Browser Run.
- Aucune requete Meta / aucune publication Instagram n'est activee.
